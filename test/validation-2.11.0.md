## 本次修复

- 2.x 标签识别补上溯兜底。原实现只认 label[for]、aria-labelledby、包裹 label、
  aria-label / placeholder / id / name，以及固定类名白名单命中的容器。
  飞书容器名为 ud-formily-item，既不含 field 也不是 form-item，三条路全不通。
  兜底分两级：先在祖先中找真正的标签节点（label / [class*=label] / [class*=title]，
  且不能包含控件本身），再退回「容器文字减去通往控件的那一支」；
  遇到含多个控件的容器即停，避免拿到隔壁字段标签拼成的一坨。
- 下拉触发候选多备一层（部分组件库真正挂事件的是更外层容器）。
- 开启提示只改变尝试顺序，不再把其余层裁掉。原实现命中提示后只试两层，
  提示一旦是错的，整页所有下拉都只试两层即放弃。
- 诊断报告的 2.x 结果改取动作最多的那一帧。页面含空 iframe 时，
  原实现「最后一个有就用谁」会把 about:blank 帧的「填入 0 项」当成结论。
- v2-core / upload-first-v2 / controlled-rerender-v2 三个夹具原本硬编码版本号断言，
  改为与引擎常量比对，版本升级不再无谓地打挂测试。

## 过程中的一次自造回归

首版把 [class*="form-item"] 加进容器白名单，结果匹配到更近的 form-item__control
（其中并无标签），讯飞夹具的标签退化成占位符「请选择」，两页因此超时。
已还原白名单，改由上溯兜底承担，四页复测通过。
