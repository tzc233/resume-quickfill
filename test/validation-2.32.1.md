# 2.32.1 本地验证记录

验证日期：2026-10-14。环境：macOS、Chrome 稳定版（Playwright `channel: 'chrome'`，headless）。

## 这一版修的是 2.32.0 的测量工具缺陷

用户用 2.32.0 跑 DeepSeek，得到「准确率 13% · 错填 0 · 漏答 62 · **用时 2.1 秒**」，
18 批原始输出**全是空**。2.1 秒跑完 18 次 API 调用（每批约 117ms）不可能是真实调用——
那 9 个「对」全部来自 6 个硬规则拦下的字段 + 3 道正确答案本就是 `none` 的陷阱题，
**报告里没有一个字来自模型**。

两处是我自己的缺陷：

1. `resolveFields` 的 `catch { raw = ''; }` 把调用失败和「模型答 none」压成同一件事。
2. `createApiSession` 为了避免回显请求头，只抛状态码不抛服务商的 message，
   把唯一能分辨 401 / 402 / 404 的信息也挡掉了。

根因则是 2.32.0 把端点写死成 DeepSeek 官方与阿里云百炼，而用户用的是
**上海交大模型网关**（`https://models.sjtu.edu.cn/api/v1/chat/completions`），
Key 在那两个域名上直接被拒。

## 改动

| 改动 | 为什么 |
| --- | --- |
| 端点 URL 改为可填，内置交大网关预设 | 端点本不该由我替用户猜 |
| 失败批次标 `failed`，汇总顶部红字提示「这份成绩不代表模型水平」 | 一轮全失败不能再汇报成绩单 |
| 错误带上服务商 `error.message`，Key 打码 | 401 / 402 / 404 要能分辨 |
| 新增「连通性自检」按钮 | 跑 71 题之前先用 1 个字段验通不通 |
| 显式 `max_tokens: 1024` / `stream: false` | 截断的 JSON 会被整批判成 none，看起来像模型集体保守 |
| 400 顶回来就去掉 `response_format` 重试一次 | 不是每个兼容代理都认它 |
| 推理文字 / ```json 围栏里的 JSON 抠出来再解析 | `deepseek-reasoner` 会在 JSON 外面裹推理过程；白名单校验照旧 |

## 结果

- `test/ai-api-v2.html` 从 13 项扩到 **24 项**断言，新增的全是错误路径：
  调用失败要标出来而不是答 none、错误里带服务商原话且 Key 被打码、
  端点没填 / 写成相对路径 / 没有 Key 都当场拦住、json 模式被拒就去掉重试、
  显式给了 max_tokens、推理文字里的 JSON 抠得出来、真不是 JSON 才按 none。
- 全量：**65 张夹具、870 项断言全部通过**（2.32.0 为 65 张 / 859 项）。
