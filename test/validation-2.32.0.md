# 2.32.0 本地验证记录

验证日期：2026-10-13。环境：macOS、Chrome 稳定版（Playwright `channel: 'chrome'`，headless）。

## 这一版做了什么

本机 Gemini Nano 在 2026-10-08 的自测里没过门槛（71 题：中文提示 55% / 错填 19，
英文提示 59% / 错填 18；门槛是**错填 0 且准确率 ≥85%**），结论是不接进填表。
用户手上有 DeepSeek / 通义千问的 API Key，这一版把**传输层**换成可选的云端模型，
好让同一套评测集去量更大的模型——**架构一个字没动**：

- 提示词（`SYSTEM` / `SYSTEM_ZH`）、档案栏白名单 `KEYS`、硬规则 `guarded`、
  不可信输入校验 `validate`、计分 `score` 全部复用本机那一套；
- 模型依旧只回答「每个字段对应档案哪一栏、第几段」，取值与写入仍由插件用本地档案完成；
- 新增 `ignoreRecord` 计分模式：段号交给引擎自己算，只量模型认栏位的本事。
  上次 19 个错填里约 10–13 个只是段号数错，两个数并排才看得清模型弱在哪一环。

**填表那条路一行都没改**，云端模型只接在实验页 `ai-lab.html` 上。

## 隐私边界（夹具钉死的性质）

`test/ai-api-v2.html` 用假端点截下请求体逐条检查，13 项断言：

| 断言 | 说明 |
| --- | --- |
| 打到了正确的端点 | DeepSeek / 百炼兼容模式各自的 `/chat/completions` |
| Key 走请求头不进提示词 | `Authorization: Bearer …`；两段消息里都搜不到 Key |
| 页面已有值不外发 | 字段对象上刻意挂了 `value`，`pick()` 必须丢掉 |
| 档案内容不外发 | 同上，刻意挂 `profile` 字段 |
| 标签照常发出 | 要发的（label / section / group / options）确实发了 |
| 硬规则拦下的字段不进字段清单 | 验证码那一条一个请求都没带上 |
| 白名单外的键按 none 处理 | 模型答 `basic.bankCard` → none |
| 越界段号、不属于本批的 id | 一律丢弃 |
| 两种计分模式 | 段号错：含段号算错填，忽略段号算正确 |

写这张夹具时我自己错了两次断言：把截获的请求头一起串进去查 Key（Key 当然在请求头里），
以及搜「验证码」时忘了系统提示本来就写着「验证码一律答 none」。两处都是断言写错，
不是代码问题，已改成只查发出去的两段消息。

## 结果

- `node test/browser-runner.cjs <test/ 下全部夹具>`：**65 张夹具、859 项断言全部通过**
  （2.31.0 为 64 张 / 846 项，本版新增一张 13 项）。
- 真实 API 的命中率**尚未测量**——需要用户在自己的浏览器里填入 Key 运行。
  未达门槛前不接入一键填充，这一条沿用 2026-10-08 的结论。

## 安装时的权限没有变化

`manifest.json` 原本就有 `host_permissions: ["<all_urls>"]`（内容脚本注入需要），
所以加 API 不会多出任何安装提示。调用发生在扩展自己的页面里，**不在内容脚本**——
否则等于把 Key 交到招聘页的 JS 手上。
