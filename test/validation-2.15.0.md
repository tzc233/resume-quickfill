## 问题一:奖项栏整栏填错

依据是荣耀校招(career.honor.com)的 2.13.0 诊断报告:8 个奖项块,每块六栏,
名称 / 类型 / 情况三栏全是同一段「日期 名称 类型 等级」的汇总文字,
8 块的获奖时间全部是第 1 条奖项的日期,级别与等级则来自另一条经历。
三个独立成因:

1. **规则不收「获奖名称 / 获奖类型」**。`award.name` 只认「奖项名称 / 奖学金名称 /
   奖项说明…」,`award.type` 只认「奖项类型 / 荣誉类型」。页面写「获奖名称」时
   一条都对不上,于是掉进规则表最后的整段兜底 `awards`(那一条本是给
   Moka「其他信息」里单个汇总文本框用的)。已补齐这两条,并新增 `award.level`。
2. **级别与等级取自另一条流**。不带前缀的「获奖级别 / 获奖等级 / 获奖类别」原先
   归 `honor.*`,即「竞赛在前、荣誉在后」的合并流;同一块里的名称取自 `awards`。
   两份排序对不上,拼出「名称是奖学金、级别却是竞赛」的记录 —— 代码注释里早已
   警告过这种错位,只是它当时假定页面一定有区块标题可以仲裁。
   现在不带前缀的写法归 `award.*`;真落在「竞赛/获奖」合并区块里时(OPPO),
   `retarget` 仍按区块标题改判回 `honor.*`。为此把「类别/级别/等级」三个维度
   在竞赛、奖学金、荣誉三份列表上补齐 —— `retarget` 的判据正是「目标列表确实
   有这个字段」,补齐后三者之间可以自由改判。
3. **段号推不动**。页面的六栏顺序是「类型、时间、名称(锚点)…」,时间排在锚点
   之前;而只有锚点和「带区块标题闸门的非锚点」才推进段号。这一页一个区块标题
   都读不出来,闸门始终关闭,8 块的时间于是全部落在第 1 段。
   现在获奖、竞赛、论文、专利、著作权这类「一条只配一个日期」的域,同一字段
   第二次出现即判为下一条,不再需要区块标题 —— 这些域的标签(获奖时间 /
   奖项名称 / 论文名称)不会和基本信息区撞名,不存在当年禁止非锚点参与计数时
   担心的「基本信息里的学历把教育段号带偏」。

另外两处:

- 「获奖情况」在页面上出现 2 次以上时,按每条奖项自己的描述处理(把同一段汇总
  灌进每一块是确定的错);只出现一次时仍是整页汇总栏,Moka 的「其他信息」不受影响。
- 档案只给第一条奖项写了描述时,其余各条用「名称 类型 等级 时间」拼一句,
  而不是留空或重复汇总。
- 并入奖项流的竞赛保留类别/级别/等级,否则那一块的三栏会因「档案中未填写」留空。

## 问题二:下拉学会了、填空没学会

`learning.js` 此前只监听 select / combobox 的选择,文本框完全不记。页面上那些
档案里压根没有的问题(年龄、就读院系、证书编号、个人成就……)每次都要重打。

现在手填的文本按「站点 + 标签」记录,下次自动填回。三条自我约束:

- **只记规则没识别出的字段**。识别出的交给档案驱动 —— 记一份既是把个人信息
  又存一处,也会让以后更新档案时被旧记忆盖掉。
- **档案永远优先**。下拉的记忆是「这个站点的选项该点哪一个」,可以压过档案;
  填空的记忆只是「档案里没有的问题上次答了什么」,只在无档案值时生效。
- **同名标签带序号**。重复的经历块里标签完全相同,不带序号会把一个值灌进每一块
  —— 那比留空更糟。认不回自己是第几个时,这次就不复用。
- 验证码、密码、动态码一类不记;单值上限 2000 字。

记忆从升级后开始积累,**不追溯**升级前手填过的内容。

## 既有失败项的处置

`baidu-style.html` 与 `jd-empty.html` 的三项断言自 2.x 导入前就是红的,根因是
`mergeAwardEntries`:页面有奖项区块、没有竞赛区块时,竞赛并进奖项流(否则整段
竞赛经历无处可去被静默丢弃)。该行为是有意的,红的是断言本身 —— 它们写在测试
档案还没有竞赛条目的时候。本次按合并后的 4 条更新断言,并保留原本要守的性质:

- `baidu-style`:第 4 栏应为并入的那条竞赛,**第 5、6 栏仍必须留空**。
- `jd-empty`:展开 4 块,四块的「获奖情况」各不相同(原断言只检查非空,
  而当时四块其实是同一段汇总文字 —— 断言名说「各不相同」却没有真的验证)。

## 边界

- 只验证本地夹具上的 DOM 结果。真实招聘页的登录态、前端校验与服务端保存仍需现场核验。
- 荣耀那一页的「获奖情况」是不是真的每块一个描述位,只能按出现次数推断;
  如果某个站点把整页汇总栏放进了重复块,这条判断会判错方向。
- 填空记忆按标签序号对位:两次访问之间经历块数量变化时,序号会错位。
  这是标签级记忆的固有限制,序号只保证不会「一个值灌满所有块」。
- 「获奖级别」取自档案 type 中的级别词(国家级/省市级/校级…)。竞赛条目把
  级别写在 result 里(如「省级二等奖」)而 type 写成「国家级」时,
  两栏会一个取 type、一个从 result 里取等级词,未必是你想要的组合 —— 请核对。
