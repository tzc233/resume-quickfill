# 2.19.0 本地验证记录

验证日期：2026-10-06。环境：macOS、Chrome 稳定版（Playwright `channel: 'chrome'`，headless）。

## 这一版改的是档案页

识别引擎（`content.js`、`engine-v2/` 的逻辑）未改动，只动了 `options.html / options.js / styles.css`。

### 修一处静默丢数据

经历里的日期框是 `<input type="month">`，出生日期是 `type="date"`。浏览器对不合格式的赋值
直接清空：档案里存着「2025」「2020.09」「2000.01.01」，页面上显示为空，
`collectList` 又跳过空值 —— **点一次保存，这条日期就从档案里删掉了**，没有任何提示。
优必选报告里「工作结束时间缺月份」这类值，正是这条路径上最容易被吞的。

现在：值合格才用 month/date 控件，否则退回文本框原样保留，并在体检里标出来。
Firefox 不支持 month，本来就是文本框，同样由体检兜住。

| 档案体检：日期缺月份/格式不对、结束早于开始、经历非倒序、姓名/手机/邮箱为空、未上传简历附件；点一条跳到并聚焦对应输入框 | 这些在诊断报告里反复出现（「档案中未填写」「日期必须包含明确的年和月」「插件中未保存简历文件」），但只有到了招聘页才看得见 |

| 经历条目上移/下移，段头显示学校/公司/名称 | 插件按顺序逐段填，第一段必须是最新的；原来顺序错了只能删掉重填 |

| 顶部区块目录，列表带段数 | 十几个区块一屏放不下；导入后一眼看出段数变化 |

## 回归

新增 `test/options-page.cjs`（25 项）：在页面脚本之前注入内存版 `browser.storage.local`，
用 Playwright 真点击、真按键、真接确认框。数据全部是「示例 XX」。

红→绿：

- 改动前的档案页上，`options-page.cjs` 第一项「不合格日期原样显示」即失败（显示为空）；
  另用同一份内存存储单独验证：保存一次后 `basic.birthday: '2000.01.01'` 与
  `education[0].startTime: '2020.09'` 都从档案里消失。改动后两者原样保留。
- 其余各项是新功能，改动前不存在对应元素。

结果：

- `node test/options-page.cjs`：**25 项全部通过**。
- `node test/browser-runner.cjs <test/ 下全部夹具>`：**55 张夹具、758 项断言全部通过**（与 2.18.0 相同，引擎未改）。
- `node test/manual-learning.cjs`：8 组全部通过。
- 1100px 与 390px 宽度截图检查：无横向滚动，目录在窄屏内横向滑动。
