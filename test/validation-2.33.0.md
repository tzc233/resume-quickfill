# 2.33.0 本地验证记录

验证日期：2026-10-14。环境：macOS、Chrome 稳定版（Playwright `channel: 'chrome'`）。

## 这一版做了什么

用户的要求是「只让我输 api，其他都帮我写好」。于是：

- 端点（`https://models.sjtu.edu.cn/api/v1/chat/completions`）、模型、批量（8）全部预置，
  页面上只剩一个 Key 输入框；Key 粘贴后 600ms 自动存入 `chrome.storage.local`，不用点保存。
  其余设置收进 `<details>` 高级设置。
- 新增**「一键跑完整套对比」**：`deepseek-chat` 与 `qwen3.8-27b` × 中文与英文提示，共 4 轮。
  每轮的**同一批回答按两种方式各算一次分**（含段号 / 段号交给引擎算）——
  不额外消耗任何调用，却能分清模型是认错栏位还是只数错段号。
  结果以矩阵呈现，绿色表示过门槛（错填 0 且准确率 ≥85%）。
- 跑之前自动做一次 `pingApi` 连通性自检；不通就直接报错，不再出成绩单。

## 新增的回归：`test/ai-lab-smoke.cjs`

2.32.0 那次事故的教训是「界面没被真的点过」。这个驱动用 Playwright 真打开 `ai-lab.html`，
桩掉 `fetch` 与 `chrome.storage`，点「一键跑完整套对比」，10 项断言：
没填 Key 时按钮禁用 / 填了就能跑 / Key 自动存下来了 / 端点已预填为交大网关 /
矩阵出四行 / 四行是两模型各中英 / 两种计分结果确实不同 / 逐字段表格 71 行 /
复制按钮启用 / **没有页面报错**。

写它的过程中它立刻抓到我两个自己的回归：

1. 界面重构后 `#api-box` 容器没了，`check()` 仍在读它 → 抛异常 → 按钮永远禁用。
2. 把表头重写那几行插在了 `const show1` 声明之前 → 暂时性死区 ReferenceError
   → 整轮被 catch 吞掉、`data-done` 永不置 1。

两处都只有真点一遍界面才会暴露，静态语法检查和夹具都测不到。
