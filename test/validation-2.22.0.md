# 2.22.0 本地验证记录

验证日期：2026-10-07。环境：macOS、Chrome 稳定版（Playwright `channel: 'chrome'`，headless）。

## 需求

用户投互联网和投央国企用两份简历。对比用户本机的两份 PDF（只在本地比对，内容不进仓库）：
差别集中在**措辞** —— 实习/项目描述（央国企版去术语化）、技能段、研究方向、
央国企版多一行校园实践 —— 以及附件 PDF 本身。

两份 PDF 之间还有两处**事实**不一致（获奖级别的写法、在读结束时间的写法），
这正说明「整份档案复制 N 份」是错的设计：复制出来的事实迟早各改各的，
而招聘方看到的是同一个人的两套事实。

## 设计：事实共享、措辞分版本

- 档案本身就是默认版本。任何对象（档案根、`basic`、每段经历）可带
  `_v: { <版本 id>: { 栏目: 措辞 } }`，只有 `versions.js` 的 `VERSIONED` 列出的栏目生效，
  事实类栏目即使写进 `_v` 也被忽略；空值等于沿用默认。
- 覆盖挂在经历条目自己身上：在默认版本里挪顺序、加新段，覆盖跟着原条目走。
- 版本自己的自定义问答排在默认问答前面（引擎先匹配者胜），默认的仍可兜底。
- 版本附件存 `resumeFiles[版本 id]`，没传就用默认附件。
- 引擎（1.x / 2.x）完全不知道版本：弹窗注入 `versions.js`，在页面里合并好、
  去掉 `_v / versions` 再交给 `__RQF_V2.fill`。

界面：

- 档案页顶部切换版本 / 新建 / 重命名 / 删除。版本模式下事实栏只读（灰），
  措辞栏显示覆盖值、占位给出默认值，经历的增删与排序只在默认版本里做。
- 弹窗出现「简历版本」下拉（没建过版本时不出现），**按网站记住选择**；
  填完的状态行写明用的是哪个版本；诊断与档案自检也按所选版本。
- 导出/导入备份带上 `resumeFiles`，导入确认里列出版本数变化。

顺带修正：档案页保存经历时只保留页面渲染的栏目，旧版遗留或页面不认识的键会被吞掉；
现在原样带回（`_v` 正是靠这一点不丢）。

## 回归

新增三组，均先在改动前确认为红：

- `test/versions.html`（12 项）：合并规则 —— 措辞覆盖、事实不随版本变、空覆盖沿用默认、
  未知版本按默认、问答优先级、引擎看不到 `_v`、不改原档案、附件回退、版本列表。
  改动前 `versions.js` 不存在。
- `test/popup-versions.cjs`（13 项）：假的 tabs / scripting / storage，`executeScript`
  的 func 就地执行，截下引擎实际拿到的档案与附件 —— 版本列表、按站点记住、换站点回默认、
  注入了 `versions.js`、引擎拿到所选版本的措辞与附件、事实照旧、无版本时不出现选择器。
  改动前首项即失败（没有选择器）。
- `test/options-page.cjs` 新增 17 项（共 59）：新建版本、事实只读、结构不可改、
  措辞占位显示默认值、覆盖落进 `_v`、默认值不被改、版本问答单独存、版本附件单独存且不动默认附件、
  切回默认、**挪顺序后覆盖跟着条目走**、删除版本清掉覆盖与附件。改动前找不到「新建版本」按钮。

结果：

- `node test/browser-runner.cjs <test/ 下全部夹具>`：**56 张夹具、774 项断言全部通过**（原 55 / 762）。
- `node test/options-page.cjs`：59 项；`node test/popup-versions.cjs`：13 项；
  `node test/manual-learning.cjs`：11 组 —— 全部通过。
- 1100px 与 390px 截图：无横向滚动。
- `pack.sh` 已把 `versions.js` 加入打包清单（漏掉的话装上的扩展弹窗会报错）。

## 已知未处理

- 版本不能删掉默认版本里有的经历段（例如某段实习只在互联网版出现）。
  需要时可把那段描述在该版本里改写成适合的说法；按段隐藏会让段号分配复杂化，暂不做。
